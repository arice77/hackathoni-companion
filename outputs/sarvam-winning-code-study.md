# What three Sarvam prizewinners actually built

**For a voice-first software companion, use SADAK’s short spoken turn, Sahayak’s explicit action result, and Quotra’s visible evidence.** Consider a user who asks in Malayalam why a button failed. The first useful response can name the control and the next step on screen. A reproducible software defect can give Devin a separate job, with the application showing its status and eventual test or PR. Waiting for the engineering job before answering would tie the conversation to its slowest step. This proposed combination is an inference from the implementations below.

Checked 20 November 2026. The Epoch snapshots are the last public commits on the day of the Bengaluru finals, 30 July. Quotra’s public Sarvam component ends on 9 August, the day it won BuildIn’ Hours. I read implementation files over HTTP and inspected published test notes. Timing figures are the authors’ measurements. I did not execute the apps or call their services. ## SADAK — keep a conversation moving

At the finals, `NpcAgent` configured Saaras v3 with automatic language selection and native transcription. Its instructions carry the role and situation. Sarvam-105B answers directly, while Bulbul v3 speaks the assigned character’s language. The code disables the model’s reasoning effort for NPC replies and uses STT turn detection with a 70 ms minimum endpointing delay. That delay is a configuration value, not an end-to-end measurement. By 22 October, the live worker and the REST helper had switched to Saaras v4. The current live-worker defaults still select Sarvam-105B and Bulbul v3. [July voice stack](https://github.com/mittal-parth/sadak/blob/ebacadea683a8fa86679c8ab1465ae7045d43535/agent.py#L117-L142) · [Turn detection](https://github.com/mittal-parth/sadak/blob/ebacadea683a8fa86679c8ab1465ae7045d43535/agent.py#L237-L251) · [October worker](https://github.com/mittal-parth/sadak/blob/fd2f383db956224863e886c0e395d71b5191b017/agent.py#L121-L138) · [October STT request](https://github.com/mittal-parth/sadak/blob/fd2f383db956224863e886c0e395d71b5191b017/game_engine/lib/sarvam.ts#L226-L242)

The worker publishes transcripts as conversation items arrive. After the NPC answers, one background task grades the completed exchange. It asks for JSON, allows a bounded timeout, ignores an unusable result, clamps the anger score and enforces a minimum number of player turns before awarding completion. An available grader can influence the game without delaying the character’s voice. A separate lesson mode matches recognized words to an expected phrase in order using edit distance. That score measures transcript agreement and cannot establish acoustic pronunciation quality. [Grader request and parser](https://github.com/mittal-parth/sadak/blob/ebacadea683a8fa86679c8ab1465ae7045d43535/agent.py#L155-L221) · [Grader scheduling](https://github.com/mittal-parth/sadak/blob/ebacadea683a8fa86679c8ab1465ae7045d43535/agent.py#L274-L310) · [Word scorer](https://github.com/mittal-parth/sadak/blob/ebacadea683a8fa86679c8ab1465ae7045d43535/game_engine/lib/game/speech-score.ts#L38-L104)

If the client lacks a LiveKit worker or the connection drops, it marks live voice unavailable. The fallback sends progressively longer recordings about every 900 ms and submits the final recording on release. Partials are display-only and skip retry; the final call can retry a transient failure. This repeatedly uploads earlier audio and costs more as a recording grows. The lesson speech route can serve a previously synthesized static line from storage and call Sarvam on a cache miss. Documented room behavior and visible transcripts make a more convincing demonstration than a prerecorded dialogue. [Room fallback](https://github.com/mittal-parth/sadak/blob/ebacadea683a8fa86679c8ab1465ae7045d43535/game_engine/lib/useLiveVoice.ts#L149-L209) · [Cumulative recordings](https://github.com/mittal-parth/sadak/blob/ebacadea683a8fa86679c8ab1465ae7045d43535/game_engine/lib/useVoice.ts#L6-L22) · [Partial and final STT](https://github.com/mittal-parth/sadak/blob/ebacadea683a8fa86679c8ab1465ae7045d43535/game_engine/app/api/stt/route.ts#L17-L58) · [Retry limits](https://github.com/mittal-parth/sadak/blob/ebacadea683a8fa86679c8ab1465ae7045d43535/game_engine/lib/retry.ts#L8-L31) · [Static speech cache](https://github.com/mittal-parth/sadak/blob/ebacadea683a8fa86679c8ab1465ae7045d43535/game_engine/app/api/speak/route.ts#L40-L50)

## Sahayak — distinguish a recognized request from a completed action

The uploaded-clip `/voice` endpoint awaits speech recognition, passes the transcript and detected language into the runtime, then optionally synthesizes a reply. A failed transcription returns an error. On TTS failure it can still return reply text, an empty audio field and a degraded flag. For non-English turns, `understand` normally translates the transcript to English. If translation fails, it passes the original text on to the multilingual model and records that fact. `localize` translates the outgoing English reply back and returns the existing text if that translation fails. The July defaults are Saarika v2.5 STT, Saaras v2.5 for speech-to-English, Sarvam-Translate v1, Sarvam-105B and Bulbul v2. November’s README says Bulbul v3, but its Python configuration still defaults to v2 and allows an environment override. The production setting is unverified. [Voice endpoint](https://github.com/akashmeruva9/sahayak-ucxp-sarvam/blob/e239560f5158fd9b1643c2aac4f6b9cb925ffcfb/backend/app/main.py#L344-L390) · [Incoming translation](https://github.com/akashmeruva9/sahayak-ucxp-sarvam/blob/e239560f5158fd9b1643c2aac4f6b9cb925ffcfb/backend/app/runtime/graph.py#L356-L385) · [Outgoing translation](https://github.com/akashmeruva9/sahayak-ucxp-sarvam/blob/e239560f5158fd9b1643c2aac4f6b9cb925ffcfb/backend/app/runtime/graph.py#L1319-L1339) · [Event defaults](https://github.com/akashmeruva9/sahayak-ucxp-sarvam/blob/e239560f5158fd9b1643c2aac4f6b9cb925ffcfb/ai_engine/config.py#L97-L135) · [November runtime](https://github.com/akashmeruva9/sahayak-ucxp-sarvam/blob/2ec6a86b211a8cff3d603c57de76cdd3cd3add98/ai_engine/config.py#L205-L232) · [November README](https://github.com/akashmeruva9/sahayak-ucxp-sarvam/blob/2ec6a86b211a8cff3d603c57de76cdd3cd3add98/README.md#L26-L31)

The Samvaad tool endpoint is the most transferable code. `run_capability` resolves an allowed business and capability, collects required fields, and requests confirmation for operations whose manifest demands it. It uses an executor, surfaces an action error, evaluates rules, renders a response, and derives `done` from the presence of a rendered receipt. The general graph’s LLM helper separately parses structured output and falls back to an empty object when it cannot obtain a usable one. Transient upstream failures have bounded retries and backoff. [Capabilities and confirmation](https://github.com/akashmeruva9/sahayak-ucxp-sarvam/blob/e239560f5158fd9b1643c2aac4f6b9cb925ffcfb/backend/app/agent_tools/execute.py#L60-L109) · [Execution and receipt](https://github.com/akashmeruva9/sahayak-ucxp-sarvam/blob/e239560f5158fd9b1643c2aac4f6b9cb925ffcfb/backend/app/agent_tools/execute.py#L111-L165) · [JSON helper](https://github.com/akashmeruva9/sahayak-ucxp-sarvam/blob/e239560f5158fd9b1643c2aac4f6b9cb925ffcfb/backend/app/runtime/llm.py#L41-L99) · [Backoff policy](https://github.com/akashmeruva9/sahayak-ucxp-sarvam/blob/e239560f5158fd9b1643c2aac4f6b9cb925ffcfb/ai_engine/utils.py#L245-L299)

**A receipt proves only what its connector did.** The Shopify reader fetches an order when a store and token are available. A configured real store with missing credentials or an upstream error returns an error. A demo store can return a deterministic fixture. The refund route looks up an amount and creates a pickup reference; the source does not submit a Shopify refund transaction. Also, the direct execution path evaluates its rules *after* calling the connector. For a companion, validate preconditions before any external write, and verify the actual screen state or external job status before saying it succeeded. [Real and fixture orders](https://github.com/akashmeruva9/sahayak-ucxp-sarvam/blob/e239560f5158fd9b1643c2aac4f6b9cb925ffcfb/backend/app/connectors/shopify.py#L218-L243) · [Refund behavior](https://github.com/akashmeruva9/sahayak-ucxp-sarvam/blob/e239560f5158fd9b1643c2aac4f6b9cb925ffcfb/backend/app/connectors/shopify.py#L247-L288) · [Order of operations](https://github.com/akashmeruva9/sahayak-ucxp-sarvam/blob/e239560f5158fd9b1643c2aac4f6b9cb925ffcfb/backend/app/agent_tools/execute.py#L111-L152)

## Quotra — make the transcript and evidence inspectable

The public repository contains Team Zen’s Sarvam component and playground. On release, the playground requests two Saaras v3 transcriptions of the same audio in parallel. One preserves code-mixed speech for display. The other requests English translation and becomes the actual question passed to the LLM with company, product and tender records. The Sarvam-105B answer must meet an answer-and-citations contract. The app translates English back to Tamil or Hindi through Sarvam-Translate v1 and sends a shortened answer to Bulbul v3. The selector and normalizer cover English, Tamil and Hindi. Malayalam would require an explicit application change. [Language choices](https://github.com/jenineeuq/quotra-sarvam-lane/blob/3a377e7e4a3178d32ad3c248f12d3d78d79a56bb/app/playground/voice/page.tsx#L35-L60) · [Actual request sequence](https://github.com/jenineeuq/quotra-sarvam-lane/blob/3a377e7e4a3178d32ad3c248f12d3d78d79a56bb/app/playground/voice/page.tsx#L185-L245) · [Speech models](https://github.com/jenineeuq/quotra-sarvam-lane/blob/3a377e7e4a3178d32ad3c248f12d3d78d79a56bb/lib/voice/sarvam.ts#L35-L46) · [Translation model](https://github.com/jenineeuq/quotra-sarvam-lane/blob/3a377e7e4a3178d32ad3c248f12d3d78d79a56bb/lib/translate/sarvam.ts#L27-L34)

`validateAskQuotraAnswer` requires answer text and well-formed references, and accepts an empty citation list. It does not check whether a cited identifier exists or a passage supports the answer. The adapter uses a wire-level JSON schema for tender verdicts, with JSON-object mode for suitable other features. A parse or validation failure gets one corrective retry. A separate robust wrapper can restart the validation cycle on a contract error, while surfacing network errors. The voice page calls ordinary `completeJSON`. A companion should verify a control or source identifier against the current screen before publishing the model’s pointer. [Citation validator](https://github.com/jenineeuq/quotra-sarvam-lane/blob/3a377e7e4a3178d32ad3c248f12d3d78d79a56bb/lib/askquotra/contract.ts#L26-L61) · [Response formats](https://github.com/jenineeuq/quotra-sarvam-lane/blob/3a377e7e4a3178d32ad3c248f12d3d78d79a56bb/lib/llm/sarvam.ts#L146-L164) · [Corrective retry](https://github.com/jenineeuq/quotra-sarvam-lane/blob/3a377e7e4a3178d32ad3c248f12d3d78d79a56bb/lib/llm/client.ts#L239-L282) · [Optional robust wrapper](https://github.com/jenineeuq/quotra-sarvam-lane/blob/3a377e7e4a3178d32ad3c248f12d3d78d79a56bb/lib/llm/sarvamRobust.ts#L31-L48) · [Voice call site](https://github.com/jenineeuq/quotra-sarvam-lane/blob/3a377e7e4a3178d32ad3c248f12d3d78d79a56bb/app/playground/voice/page.tsx#L209-L223)

The timing tests synthesized two spoken questions, transcribed them sequentially in both modes, queried fixture records, translated the answer and synthesized speech. Those totals include input generation and are not a stopwatch measurement from a human releasing the button to hearing first audio. The harness even substitutes the question text if English transcription returns empty. The actual UI passes the translated transcript through directly. A later human-mic test exposed a symptom the clean test missed: different spoken questions produced the same generic answer. The team added diagnostics and short-clip guards. Their notes leave the specific audio cause unresolved. Also, their separate phone prototype configures its TTS language once at startup, so its multilingual LLM cannot by itself guarantee a matching spoken voice. ## An implementation pattern for a Sarvam and Devin companion

1. **Hear and show.** Capture one push-to-talk request and display the transcript the reasoning model actually receives. If the transcript is blank, prompt for a repeat or typed input. Keep identifiers such as a button label or error code exactly as they appeared on the screen. This addresses the failure Quotra observed. [Actual human-mic report](https://github.com/jenineeuq/quotra-sarvam-lane/blob/3a377e7e4a3178d32ad3c248f12d3d78d79a56bb/MERGE-NOTES.md#L815-L844)
2. **Speak early.** Use the transcript and a small set of observed controls to produce a short spoken instruction and one control ID. Validate that ID locally and highlight it. Keep long analysis, a second model and repair work out of the first audio path. Measure microphone release to first audible byte, then time to an independently verified outcome. SADAK’s background grader and Quotra’s measured delay explain the distinction. [Background task](https://github.com/mittal-parth/sadak/blob/ebacadea683a8fa86679c8ab1465ae7045d43535/agent.py#L274-L310) · [Quotra timings](https://github.com/jenineeuq/quotra-sarvam-lane/blob/3a377e7e4a3178d32ad3c248f12d3d78d79a56bb/MERGE-NOTES.md#L479-L485)
3. **Give Devin an inspectable engineering job.** For an unresolved, reproducible problem in an authorized product repository, let the user review the redacted steps, expected and observed state, app version and screenshot crop. Submit on confirmation. Store the returned session ID as **submitted**. Later show the linked change and test result separately. Review the actual result before the companion calls the issue fixed. The cited winners supply the conversational and receipt patterns; this Devin handoff is a proposed addition. [Receipt contract](https://github.com/akashmeruva9/sahayak-ucxp-sarvam/blob/e239560f5158fd9b1643c2aac4f6b9cb925ffcfb/backend/app/agent_tools/execute.py#L141-L165)
4. **Test the failures a judge can cause.** Try a real Malayalam-English utterance with an English button name, an empty or noisy clip, a stale control after a screen change, unavailable TTS and a pending or failed repair. Check actual captions, highlighted control, audio and task state. For a recorded case, label the recording in the interface. Keep service credentials behind the backend. Quotra’s browser bring-your-own-key playground can read a key from local storage or a public build variable. [Browser key resolution](https://github.com/jenineeuq/quotra-sarvam-lane/blob/3a377e7e4a3178d32ad3c248f12d3d78d79a56bb/lib/voice/sarvam.ts#L92-L114) · [Text survives TTS failure](https://github.com/akashmeruva9/sahayak-ucxp-sarvam/blob/e239560f5158fd9b1643c2aac4f6b9cb925ffcfb/backend/app/main.py#L357-L390)
